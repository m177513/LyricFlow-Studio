# 새 ZIP 설치 검증 — 2026-10-19

## 결론과 범위

README의 필수 프로그램을 설치한 Windows에서 `install_windows.bat` → `run_windows.bat`으로 실행할 수 있도록 아래 문제를 수정했습니다. Codex/Claude 프로그램·구독·API 키를 실행 의존성으로 사용하지 않습니다.

**기존 Windows PC에서 앱 환경을 새로 만든 시험입니다. Windows를 새로 설치한 VM 시험은 아닙니다.** OS의 FFmpeg, Python 인터프리터, 시스템 DLL, 글꼴, 드라이버는 기존 설치를 사용했습니다. 필수 프로그램의 설치 마법사 자체와 모든 Windows 환경을 검증했다는 뜻은 아닙니다.

## 시험 방법

- 공개 저장소 ZIP을 인증 없이 다운로드했습니다. 시작 소스는 `7cb8bbb007951c742a1ed52992cc55ec222ed023`입니다.
- 기존 개발 폴더·가상환경·모델을 사용하지 않고 별도 폴더에서 설치했습니다. 최초 시험의 npm/pip/Hugging Face 캐시는 빈 전용 폴더였습니다.
- 수정 후 **또 다른 빈 폴더**에서 전체 설치를 다시 실행했습니다. 두 번째 설치는 시험 중 내려받은 패키지 캐시만 재사용했으며, `node_modules`, `.venv`, `.venv-audio`는 새로 만들었습니다.
- Node.js 22.23.3 공식 ZIP(SHA-256 확인), Python 3.12.3, FFmpeg/ffprobe 8.1, Windows x64 빌드 26200에서 확인했습니다.
- 시험 자료는 저장소의 합성 WAV 2개, 설명용 문장, 데모 이미지뿐입니다. 개인 곡·가사·이미지는 사용하거나 배포하지 않았습니다.

## 발견한 문제와 수정

1. Python 3.12가 있어도 설치기가 `py -3.11`만 찾던 문제: 3.11/3.12를 확인하고 두 가상환경에 같은 인터프리터를 사용합니다.
2. faster-whisper 1.2.1과 새 PyAV 19의 실제 분석 충돌: `av==18.1.0`을 고정했습니다. [upstream 이슈](https://github.com/SYSTRAN/faster-whisper/issues/1589)의 `metadata_errors` 인자 제거 문제와 동일하게 재현됐습니다.
3. 보컬 모델 설정 파일의 첫 주소가 404일 때 공식 대체 주소로 넘어가지 못하던 문제: 다운로드 오류를 audio-separator가 처리하는 `RuntimeError`로 전달합니다. 인증서 검증을 끄거나 임의 미러를 추가하지 않습니다.
4. Windows 브라우저 자동 열기 실패: `cmd.exe`에 전달하는 따옴표가 잘못 이스케이프되지 않도록 고쳤습니다. 수정 후 배치 파일이 자동으로 연 Chrome 탭을 확인했습니다.
5. 설치 점검이 실패해도 성공으로 표시되던 문제: 오류 시 비정상 종료 코드를 반환합니다. 짧은 메모리 WAV를 실제로 디코딩하고 보컬 분리 모듈을 불러오는 점검도 추가했습니다.
6. 새 ZIP에 없는 `verification` 폴더에 테스트 결과를 쓰던 문제: SRT 내용을 검증한 뒤 불필요한 파일을 쓰지 않도록 바꿨습니다.

데모 자동 준비, 실행 전 Node 버전·Player 빌드 확인, 설치 실패 안내도 보완했습니다.

## 남아 있는 확인 범위

- 새 Windows VM, Python 3.11 실설치, 표준 사용자 계정의 전체 설치 마법사
- CUDA Whisper, 큰 모델의 최초 다운로드·추론, 선택 stable-ts 설치, 모든 GPU·드라이버 조합
- 실제 노래 청취 검수, 전체 플레이리스트·쇼츠, Suno 사이트의 실시간 가져오기
- npm audit는 기존 잠금 파일에서 `fast-uri` moderate 1건, `source-map-js` high 1건을 보고했습니다. 설치 및 위 실행은 통과했으나 이 시험에서 해당 의존성은 업데이트하지 않았습니다. 보안 취약점이 없다는 판정은 아닙니다.

설치 로그·환경 freeze·모델·출력 MP4는 검증 PC에만 보관하며 소스 ZIP에는 넣지 않습니다. 다운로드 서버나 향후 간접 의존성 변경으로 결과가 달라질 수 있으므로, 오류가 생기면 README의 문제 해결 절차와 `npm run doctor` 출력을 확인하세요.
