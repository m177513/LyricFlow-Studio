# 0.1 → 0.2 정리 및 변환 경계

0.2를 실행 기준본으로 삼는다. 기존 0.1 폴더의 `.lyricflow/project.json`이 있고 0.2의 `.lyricflow-remotion/project.json`이 없을 때만, 폴더를 처음 열면서 새 0.2 저장소를 만든다. 0.1 원본 파일은 읽기만 하며 덮어쓰지 않는다.

## 가져오는 것

- 원문 가사(`lyrics`)와 표시 줄 순서
- 파일명·제목·곡 순서
- 공통 커버 이미지
- 0.1의 실제 매칭(`matched`, `partial`) 또는 수동(`manual`) 타이밍
- 0.1 화면 설정 중 0.2가 지원하는 캔버스·FPS·글자 크기·색·하단 위치

가져온 타이밍에는 `legacy_import` 표시를 남겨 0.2 검수 대상으로 만든다. 0.1의 `manual` 타이밍은 `locked`로 보호하지만, 오디오 바이트 해시를 기록하지 않았던 형식이므로 첫 0.2 검수는 필요하다.

## 버리는 것

- `interpolated`·`evenly_spaced` 타이밍: 시간을 새로 믿거나 채우지 않고 `null`로 둔다.
- 0.1의 직접 FFmpeg/ASS 렌더 결과: 0.2의 동일 Remotion 미리보기·출력 계약과 다르므로 출력으로 승격하지 않는다.
- PySide6 화면, Demucs 보컬 분리, 주파수 시각화, 0.1 전용 파이프라인·설정
- 0.1의 Whisper 단어 배열: 0.2 정렬기의 증거 형식과 다르므로 재분석 입력으로 재사용하지 않는다.

변환 뒤에는 `sourceLyrics` 원문, 현재 음원·이미지 파일, 수정 이력이 각각 0.2 저장소에 남는다. 이후 오디오 바이트가 바뀌면 0.2의 기존 타이밍 무효화 규칙이 적용된다.
